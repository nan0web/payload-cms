## 📋 Задача: Data-Driven Payload Configurator & i18n Editor (OLMUI)

### Контекст та Проблема
Редагування конфігурацій плагінів та словників перекладів зараз вимагає ручного редагування файлів конфігу у коді або прямих правок JS/JSON файлів перекладів. Необхідний автономний візуальний редактор конфігурацій і перекладів на базі самого Payload CMS.

### Вимоги до реалізації:
1. **Команда запуску**:
   - Реалізація CLI-команди або dev-скрипта `pnpm cms:config` / `pnpm cms:i18n`.
2. **Легковажне сховище (Zero-Postgres Dev)**:
   - Використання швидкої **SQLite** БД (in-memory / file-based) для локального dev-сеансу без необхідності підняття важкого PostgreSQL.
3. **Незмінність схеми ключів (Schema Immutability)**:
   - Ключі беруться напряму зі сканування `Model-as-Schema` (`Model.UI`) за допомогою `@nan0web/i18n`.
   - Користувач не може видалити або додати довільний ключ у CMS (схема захищена), він лише заповнює/редагує значення перекладів для різних мов.
   - Додавання нової мови генерує повний набір обов'язкових полів під усі наявні в моделі ключі.
4. **Двостороннє збереження (Data-driven Write-back)**:
   - Зміни з адмінки оновлюють файли конфігурації та словники проєкту у форматах `t.json`, `t.nan0`, `t.yaml` згідно зі стандартами `@nan0web/db`.

### Definition of Done:
Команда `pnpm cms:config` запускає Payload з формами конфігурації плагінів та перекладів, ключі суворо валідуються за `Model-as-Schema`, дані зберігаються на диск.

## 🚀 Задача: Client-Side Zero-Hosting Payload Demo (In-Browser / WebContainers / IndexedDB)

### Мета та Контекст
Створення повністю автономної демонстраційної версії адмін-панелі Payload CMS для публічної презентації всіх плагінів (`@nan0web/payload-*`), яка працює на 100% на стороні клієнта (Zero-Hosting / In-Browser) з нульовим навантаженням на сервер.

### Ключові Вимоги та Архітектура:
1. **Zero-Hosting (100% In-Browser Execution):**
   - Робота адмінки без потреби у постійно активному бекенд-сервері чи виділеній інфраструктурі.
   - Розгортання у вигляді статичного сайту (Static Hosting / GitHub Pages / Cloudflare Pages).
   - Запуск та виконання Node.js рантайму прямо у браузері через WebContainers (WebAssembly) або повний клієнтський мок/сервіс-воркер (MSW).

2. **Легковажна In-Browser База Даних (No Heavy SQL / Zero-Postgres):**
   - Відмова від важких зовнішніх СУБД (PostgreSQL / MySQL) на користь клієнтських сховищ:
     - Браузерна **IndexedDB** або **OPFS** (Origin Private File System).
     - **SQLite WASM** (in-memory або з персистентністю в IndexedDB через `sql.js` / `@payloadcms/db-sqlite` у WebContainer).
   - Миттєвий старт з предзавантаженим seed-станом (демо-контент, релізи, тури, інструкції).

3. **Презентація Всіх Пакетів Екосистеми (@nan0web/payload-*):**
   - Демонстрація плагінів у реальному інтерактивному інтерфейсі:
     - `@nan0web/payload-release`: перегляд специфікацій `task.md`, живий інтерактивний Product Tour (`v0.2.0`).
     - `@nan0web/payload-signin-theme-state`: перемикання теми, Zero-Flicker First Paint.
     - `@nan0web/payload-self-manual`: інтерактивна документація плагінів усередині адмінки.
     - `@nan0web/payload-browse-by-folder`: браузинг медіатека за папками.
     - `@nan0web/payload-keyboard-accessibility`: навігація клавіатурою.

4. **Ізоляція та Безпека:**
   - Кожен відвідувач отримує власну ізольовану сесію в браузері.
   - Дії публічних користувачів не можуть зламати спільну базу чи вплинути на інших відвідувачів.
   - Можливість скидання демо-сесії до початкового стану однією кнопкою ("Reset Demo").

### Definition of Done (DoD):
- [ ] Підготовлено збірку/стенд, який піднімає Payload CMS виключно у браузері відвідувача.
- [ ] База даних ініціалізується в браузері (SQLite WASM / IndexedDB).
- [ ] Відсутнє будь-яке навантаження на бекенд (Zero-Hosting).
- [ ] Усі плагіни доступні для інтерактивного тестування з працюючими турами релізів.
