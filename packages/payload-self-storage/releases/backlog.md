# @nan0web/payload-self-storage — Беклог задач

## 📋 Задача 1: Фізичне збереження за структурою папок (`sourcePath` / `folder-aware`)

### Контекст та Проблема
Зараз стандартний `upload` у Payload записує всі файли в єдину плоску директорію `storage/` або `media/`.
При міграції та збереженні ієрархії виникає потреба зберігати файли фізично на диску у вкладених папках відповідно до `sourcePath` або обраної віртуальної папки Payload (`payload-folders`).

### Вимоги до реалізації:
1. **Перехоплення хуків збереження**:
   - Перехоплювати `beforeChange` / `afterRead` колекції `media` (та інших upload-колекцій).
2. **Фізичне збереження на диску**:
   - Зберігати файл на диску фізично за вкладеним шляхом `sourcePath` (наприклад, `media/img/products/cards/Visa-Instant.webp` або `storage/<folder_path>/<filename>`).
3. **Формування канонічного `url`**:
   - Формувати `url` відповідно до фізичного шляху, забезпечуючи 100% сумісність з існуючими посиланнями сайту та SSG/RSC рендерингом.
4. **Запобігання дублікатам-суфіксам**:
   - Запобігати автоматичній генерації суфіксів `-1`, `-2`, якщо файл з таким хешем/шляхом уже існує.
5. **Контрактні тести (TDD)**:
   - Додати контрактні тести на створення, читання та перевірку фізичного розташування файлів на файловій системі.
