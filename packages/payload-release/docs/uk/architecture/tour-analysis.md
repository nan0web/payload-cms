## 2. Формат та місце зберігання конфігурації туру: `tour.nan0`

### 2.1 Чому окремий файл `tour.nan0` у теці релізу, а не засмічення `task.md`?

1. **Чистота відповідальності (Separation of Concerns):**
   - `task.md` — це паспорт інженерних завдань, технічних вимог та контрактів (PM-as-Code).
   - `tour.nan0` — це сценарій візуальної взаємодії для користувача/редактора в UI.
2. **Локалізація та паритет мов:**
   - Для кожної мови створюється свій файл туру або секція:
     `releases/{major}/{minor}/v{version}/tour.nan0` (або `releases/.../uk/tour.nan0`).
3. **Єдине Джерело Правди: Версія як єдиний ідентифікатор:**
   - Немає потреби вигадувати штучні поля типу `id: "v0.5.0-ingestion-tour"`.
   - **Ідентифікатором туру є сама версія релізу: `v0.5.0`** (або SemVer `0.5.0`). Жодних зайвих сутностей!

### 2.2 Приклад специфікації `tour.nan0` з інтерактивними кроками

Тур підтримує два типи кроків:

1. **Інформаційний (`action: next`)**: користувач читає підказку і тисне «Далі».
2. **Інтерактивна дія (`action: click` або `action: input`)**: тур підсвічує кнопку (наприклад, `«Створити»`) і чекає, поки користувач **фізично на неї натисне**, щоб перейти далі або відкрити форму!

```yaml
version: 0.5.0
title: 'Оновлення v0.5.0: Моніторинг джерел та імпорт новин'

steps:
  # Крок 1: Бокове меню — перехід до джерел
  - step: 1
    route: '/admin'
    target: "nav a[href*='/admin/collections/sources']"
    title: 'Розділ Моніторингу'
    content: 'У цьому релізі додано автономний збір новин. Перейдіть до розділу Джерела.'
    position: 'right'
    action: 'click' # Тур пропонує клікнути на пункт меню, або клікає при натисканні 'Далі'

  # Крок 2: Таблиця джерел — кнопка Створити
  - step: 2
    route: '/admin/collections/sources'
    target: "a[href*='/admin/collections/sources/create']"
    title: 'Додавання нового каналу'
    content: 'Натисніть кнопку «Створити», щоб зареєструвати новий Telegram-канал або RSS.'
    position: 'bottom'
    action: 'click' # Очікує натискання кнопки користувачем

  # Крок 3: Всередині форми — вибір типу джерела
  - step: 3
    route: '/admin/collections/sources/create'
    waitFor: '#field-type' # Чекає завершення рендеру форми
    target: '#field-type'
    title: 'Тип джерела новин'
    content: "Оберіть 'telegram' для каналу або 'rss' для новинного сайту."
    action: 'select'
    value: telegram
    position: 'bottom'

  # Крок 4: Всередині форми — введення посилання
  - step: 4
    route: '/admin/collections/sources/create'
    target: 'input#field-url'
    title: 'Адреса каналу (URL)'
    content: 'Введіть посилання, наприклад: https://t.me/absolutionlab'
    action: 'fill'
    value: 'https://t.me/absolutionlab'
    position: 'top'
```

## 3. Керування станом та швидкий перегляд прогресу

### 3.1 Ключ у LocalStorage

Для максимальної швидкості без затримки запитів до мережі стан записується в браузері:

```javascript
// Ключ у LocalStorage:
localStorage.getItem('@nan0web/release.tour')
// Формат значення:
// "0.5.0#complete"  -> поточний реліз пройдено повністю
// "0.5.0#3"         -> користувач зупинився на кроці 3
```

### 3.2 Логіка кількох пропущених турів (Multi-Version Catch-up)

Якщо користувач не заходив тривалий час і пропустив, наприклад, версії `v0.4.0` та `v0.5.0`:

1. **Правило актуальності:** За замовчуванням система пропонує тур **останнього актуального релізу** (`v0.5.0`), щоб не змушувати проходити застарілі інтерфейси.
2. **Архів турів у розділі релізів:**
   - На сторінці перегляду будь-якого релізу (`/admin/collections/releases`) або у віджеті версії доступна кнопка:
     `[ 👁️ Запустити тур релізу v0.4.0 ]`.
   - Це дозволяє в будь-який момент запустити тур будь-якої минулої версії!

### 3.3 Серверне збереження (User Preferences)

У профіль користувача Payload CMS (`users.preferences`) зберігається об'єкт:

```json
{
	"tours": {
		"0.4.0": { "completed": true, "completedAt": "2026-10-15T10:00:00Z" },
		"0.5.0": { "completed": false, "lastStep": 2 }
	}
}
```

## 4. Де зберігаються підказки туру та багатомовність (Стандарт Варіанта Б)

Підказки туру зберігаються **виключно у релізах** за стандартом **Варіанта Б (Автономні Декларативні Маніфести)**:

1. **Файлова структура:**
   - Базовий тур (за замовчуванням — англійська мова):  
     `releases/{major}/{minor}/v{version}/tour.nan0`
   - Локалізовані повні сценарії туру (наприклад, українська):  
     `releases/{major}/{minor}/v{version}/uk/tour.nan0` (або `tour.uk.nan0`)
2. **Переваги Варіанта Б:**
   - **Zero Hack / Чистота даних:** Масиви кроків не розриваються на штучні словникові ключі та не потребують нетипового глибокого патчингу елементів масивів.
   - **Повна ізоляція мовних сценаріїв:** Кожен сценарій є цілісним, має власні заголовки, підказки, а за потреби — специфічні селектори чи дії під локаль.
   - **Автоматичний Fallback:** Якщо для певної мови немає окремого файлу `tour.nan0` у її підпапці, система автоматично надає базовий `tour.nan0` (англійською).
3. **Визначення мови:**
   - Мова зчитується з профілю поточного користувача Payload CMS (`user.language` або `localStorage['@payload-language']`), атрибута `html[lang]` або навігатора.
   - Клієнтський компонент `TourLauncher` викликає `GET /api/releases/:version/tour?locale=<lang>` та запускає відповідний маніфест.
